# Sprint 06 — Integração Core + Base Operacional

## Objetivo

Transformar o SIGIN Core em uma plataforma ERP utilizável,
criando a base operacional para usuários e controle de acesso.

A prioridade desta sprint foi preparar o Core para utilização real,
sem criação de novas regras comerciais.

---

# 1. Módulo Usuário / Identidade

## Objetivo

Criar a camada de identidade e autenticação do SIGIN.

Decisão arquitetural:

Pessoa continua sendo a identidade de negócio.

Usuário representa exclusivamente uma credencial de acesso.

---

## Implementado

- Cadastro de usuários
- Usuário vinculado à Pessoa
- Controle de ativo/inativo
- Login
- Senha criptografada
- Último login
- JWT

---

# 2. Controle de acesso

## Estrutura implementada

Usuario

↓

UsuarioPerfil

↓

Perfil

↓

PerfilPermissao

↓

Permissao


---

## Regras definidas

- Permissões não ficam diretamente no usuário.
- Usuário recebe permissões através de perfis.
- Perfis podem ser reutilizados.
- Permissões utilizam código técnico.

Exemplo:

PRODUTO_VISUALIZAR

PRODUTO_EDITAR

PEDIDO_CANCELAR

---

# 3. Spring Security

Implementado:

- SecurityFilterChain
- JWT Filter
- UserDetailsService customizado
- Authentication via Bearer Token
- Authorities carregadas dinamicamente

---

# 4. Validações realizadas

## Sem autenticação

Endpoint protegido:

GET /produtos

Resultado:

403 Forbidden


## Com autenticação

Usuário com permissão:

PRODUTO_VISUALIZAR

Resultado:

200 OK


## Sem permissão

Usuário autenticado sem autoridade:

403 Forbidden

---

# 5. Decisões arquiteturais

## IAM

O módulo Usuario passa a representar a camada de identidade do SIGIN.

Responsabilidades:

- autenticação
- autorização
- perfis
- permissões

Não possui regras comerciais.
